# Push to Segment Skill

Use whenever the user wants to push contacts from a stored result set into an HP Segment via natural language. The `/push-to-segment` slash command also triggers this flow via `hp-dataops`.

---

## How It Works

`hp.pushToSegment()` is a **built-in helper available in the execute sandbox** — it handles all four steps automatically:

| Step | Action |
|------|--------|
| 1 | `PATCH /api/sources/{sourceId}` — create/configure an `importFromWebhook` source |
| 2 | `POST /api/segments` — create a new segment (or find existing if `segmentId` given) |
| 3 | `GET → PATCH /api/segments/{id}` — safely link the source to the segment |
| 4 | `POST /api/contacts/{sourceId}/bulk-upsert-contacts` — push records in 1000-row batches |

---

## Tool Call

Always use the **`execute`** MCP tool with `hp.pushToSegment()`:

```javascript
async ({ hp }) => {
  return await hp.pushToSegment('RESULT_SET_ID', {
    // sourceName is auto-generated by the server — do NOT pass it
    fieldMapping: [
      { sourceFieldName: 'FullName',   hpFieldName: 'contact.fullName'       },
      { sourceFieldName: 'Email',      hpFieldName: 'contact.emails'         },
      { sourceFieldName: 'LinkedIn',   hpFieldName: 'contact.linkedIn'       },
      { sourceFieldName: 'Title',      hpFieldName: 'contact.title'          },
      { sourceFieldName: 'Company',    hpFieldName: 'company.companyName'    },
      { sourceFieldName: 'Website',    hpFieldName: 'company.companyWebsite' },
    ],
    segmentName:  'VP_Sales_2025-06-15_14-30_agent',  // auto-generated: 2-word-desc_YYYY-MM-DD_HH-MM_agent
    // segmentId: 'EXISTING_SEGMENT_UUID',             // or add to an existing segment
  });
}
```

**Returns**: `{ source_id, source_name, segment_id, segment_name, pushed, batches, message }`

---

## fieldMapping Rules

- `sourceFieldName` — the key name as it appears in the result set records
- `hpFieldName` — HP field path; **must** use `contact.*` or `company.*` prefix

Common mappings:

| sourceFieldName | hpFieldName |
|----------------|-------------|
| FullName / Name | `contact.fullName` |
| Email | `contact.emails` |
| LinkedIn | `contact.linkedIn` |
| Title / Role | `contact.title` |
| Phone | `contact.phoneNumbers` |
| Company | `company.companyName` |
| Website / Domain | `company.companyWebsite` |
| Country | `contact.country` |

If `fieldMapping` is omitted, result set records are passed through as-is (flattened).

## Conversation Protocol

When the user asks to push contacts to a segment:

1. **Confirm** the active result set ID (from runtime context `Active Resultset ID`, or ask the user).
2. **Auto-generate a segment name** — do NOT ask the user. Use this exact format:

   ```
   <2-word-desc>_YYYY-MM-DD_HH-MM_agent
   ```

   - Description: maximum **two words**, derived from what was discovered (e.g. the query topic or filter).
   - Use the **current date and time**.
   - Always end with `_agent` suffix.

   Examples:
   - `VP_Sales_2025-06-15_14-30_agent`
   - `SaaS_Chennai_2025-06-15_09-05_agent`
   - `ICP_Contacts_2025-06-15_11-45_agent`
   - `Finance_Companies_2025-06-15_08-00_agent`

3. **Source name** — auto-generated by the API server; do NOT pass `sourceName` or `sourceId` in the call.
4. **Field mapping** — if `schema_summary` is in context, auto-propose and apply without asking. Only pause if fields are completely ambiguous.
5. **Execute** `hp.pushToSegment(...)` immediately with the generated segment name.
6. **Report** the result: segment name, records pushed, batch count.

### Auto-propose fieldMapping from schema_summary

If `schema_summary` is available in context, scan field names and suggest mappings:

| Field contains | Suggest |
|---|---|
| "name" / "fullname" | `contact.fullName` |
| "email" | `contact.emails` |
| "linkedin" | `contact.linkedIn` |
| "title" / "role" | `contact.title` |
| "phone" | `contact.phoneNumbers` |
| "company" (not "website") | `company.companyName` |
| "website" / "domain" | `company.companyWebsite` |
| "country" | `contact.country` |

Present the proposed mapping to the user for confirmation before executing.
