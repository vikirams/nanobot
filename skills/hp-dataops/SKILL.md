# HP Data Operations Skill

Injected after `/merge`, `/dedupe`, or `/push-to-segment` executes.

---

## Active Resultset

**CRITICAL**: When `Active Resultset ID` is present in the runtime context:

1. Pass it directly as `resultset_id` to `mcp_execute` — the server pre-loads `const data = [...]`.
2. **Do NOT call `list_resultsets`** to find data that's already active in context.

---

## 2-Step Tool Protocol (for follow-up requests)

**Step 1** — `mcp_<server>_search` to find the right endpoint.
**Step 2** — `mcp_<server>_execute` to run the code. Pass `resultset_id` when working with stored data.

Skip Step 1 only when the endpoint is already known from this session.

---

## Merge

Merges two stored result sets with deduplication.

**Strategies**:

| Strategy | Deduplication logic |
|----------|-------------------|
| `email_linkedin_domain` (default) | Match on email + LinkedIn URL + company domain |
| `email_only` | Match on email address only |
| `all` | Aggressive — any shared field counts as a match |

Requires two `result_set_id` values. Produces a new merged resultset.

---

## Dedupe (2 steps — always confirm before acting)

Scoped to a segment. **Run Step 1 first, show results to user, only run Step 2 after review.**

- **Step 1** — `fetch-duplicates`: previews matched duplicates within the segment.
- **Step 2** — `dedupe-contacts`: removes duplicates after user confirms.

Default dedupe fields: `emails`, `linkedIn`.

Never run Step 2 without Step 1 confirmation — destructive and irreversible.

## Push to Segment

Pushes contacts from a stored result set into an HP Segment. The full protocol (field mapping, source creation, segment linking) is handled by `hp.pushToSegment()` — a built-in helper available in the execute sandbox:

```javascript
async ({ hp }) => {
  return await hp.pushToSegment('RESULT_SET_ID', {
    // sourceName is auto-generated by the server — do NOT pass it
    fieldMapping: [
      { sourceFieldName: 'FullName',  hpFieldName: 'contact.fullName'       },
      { sourceFieldName: 'Email',     hpFieldName: 'contact.emails'         },
      { sourceFieldName: 'LinkedIn',  hpFieldName: 'contact.linkedIn'       },
      { sourceFieldName: 'Title',     hpFieldName: 'contact.title'          },
      { sourceFieldName: 'Company',   hpFieldName: 'company.companyName'    },
      { sourceFieldName: 'Website',   hpFieldName: 'company.companyWebsite' },
    ],
    segmentName: 'VP_Sales_2025-06-15_14-30_agent',  // 2-word-desc_YYYY-MM-DD_HH-MM_agent
    // segmentId: 'EXISTING_UUID',                   // or add to existing segment
  });
}
```

**Returns**: `{ source_id, source_name, segment_id, segment_name, pushed, batches, message }`

`hpFieldName` must use `contact.*` or `company.*` prefix. If `fieldMapping` is omitted, records are passed through as-is.

**Segment naming** — auto-generate without asking the user, using this exact format:

```
<2-word-desc>_YYYY-MM-DD_HH-MM_agent
```

Max two words for the description, derived from the data (e.g. `VP_Sales`, `SaaS_Chennai`, `ICP_Contacts`). Always end with `_agent`. Use current date and time.

**Source name** — auto-generated server-side; do NOT pass `sourceName` in the call.

Before executing, confirm only: result set ID (from context or user).

## Export and Push (after any fetch)

- **Download CSV** — search for `export` pattern, then execute via `mcp_execute`.
- **Push to Webhook** — search for `push_to_webhook` pattern, then execute via `mcp_execute`.

---

## Error Handling

- First failure: analyse the error, adjust, retry once.
- Second failure: stop. Tell the user the capability is unavailable.
- For dedupe: if Step 2 is attempted without Step 1, warn the user before proceeding.
